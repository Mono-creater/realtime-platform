# 从模拟模式切换为真实模式 —— 详细操作文档

> 适用项目：`D:\realtime-platform\realtime-platform-main`（Vue3 + Express + Socket.IO + Prisma/MySQL + Modbus TCP 采集汇川 H5U PLC）
> 编写日期：2026-09-06
> 关联文档：《PLC接入操作手册.md》（协议、寄存器、真实联调细节）、《云服务器部署方案.md》（上云部署）
> 本文聚焦一件事：**平台如何从"模拟模式"切到"真实模式"，以及如何切回来**。

---

## 1. 先弄清三种运行模式

平台不是"模拟/真实"两个开关，而是三种运行状态，由 `.env` 的 `PLC_MODE` 和 `PLC_HOST/PORT` 组合决定：

| 模式 | PLC_MODE | PLC_HOST / PORT | 数据来源 | 数据库(Prisma) | 控制闭环 | 页面数据源标签 |
|---|---|---|---|---|---|---|
| **纯模拟** | `simulation` | 不连接任何 PLC | server.js 自生成随机数（温度 20~90°C、压力 50~1200kPa、湿度 20~95%，30% 概率注入异常） | ❌ 跳过（告警只存内存，重启即丢） | 内部植物模型（假闭环） | "模拟数据" |
| **模拟器闭环** | `real` | `127.0.0.1` / `1502` | `plc-simulator.js`（Modbus TCP 从站，忠实模拟 H5U 固件：寄存器、状态字、序号、子包、FC16 写回） | ✅ 会加载 | 真实 Modbus 闭环（写 30021/30022） | "PLC 实时数据" |
| **真实 PLC** | `real` | `192.168.1.88` / `502`（示例） | 现场汇川 H5U 实体机 | ✅ 会加载 | 真实 Modbus 闭环 | "PLC 实时数据" |

关键点：
- **模拟器闭环 ≠ 纯模拟**。模拟器走的是**真实 Modbus TCP 协议栈**，平台无法区分它与真机（操作手册 1.2 明确）。它和真实 PLC 的唯一差别就是 `PLC_HOST` / `PLC_PORT` 两个地址。**推荐一切切换都以"模拟器闭环"为中间站**：先在模拟器上把整条链路跑通，再改地址指向真机。
- **真实模式（`real`）不保证拿到真实数据**：启动或切换时连不上 PLC，平台会**自动回退到纯模拟**并打印警告（见 4.3）。
- 旧固件（状态字 bit6=0 且序号=0）走"平台侧 10 条缓冲均值"回退路径，页面标签为"旧固件回退"，不影响本切换流程。

## 2. 切换机制总览：三条途径

| 途径 | 方式 | 生效范围 | 重启要求 | 适用 |
|---|---|---|---|---|
| **A. 改 .env（永久切换）** | 编辑 `realtime-platform-main/.env`，改 `PLC_MODE`、`PLC_HOST/PORT`、寄存器地址等 | 永久，重启后仍保持 | **必须重启** server | 确定要长期跑真实模式（推荐） |
| **B. 运行时 API（临时切换）** | `POST /api/plc/mode {"mode":"real"}` | 仅当前进程运行期 | 不需要重启，但**重启后回到 .env 原值** | 快速验证、演示、排查 |
| **C. 前端按钮（临时切换）** | 受电弓监测页（MonitorCar）的"模拟/真实"切换按钮 | 同 B（内部就是调 B 的 API） | 不需要 | 有 UI 时最方便 |

### 2.1 切换行为的三个代码事实（务必理解）

1. **运行时切 `real` 不重新读取 .env**。`PLC_HOST/PORT/PLC_REG_*` 都是进程启动时读入内存的。改了 .env 但没重启，用 API 切到真实模式，连的还是**旧地址**。
2. **数据库只在启动时按初始模式加载**。`prisma` 仅在启动那一刻 `PLC_MODE != 'simulation'` 时初始化（server.js 第 50 行）。如果启动时是模拟模式，运行中即使切到 `real`，`prisma` 仍为 `null`，告警**不会落库**。要数据库生效必须：`PLC_MODE=real` + 配好 `DATABASE_URL` + **重启**。
3. **切 `real` 失败会自动回退，且不会自动重试**。`connectPLC()` 失败 → `SIMULATION_MODE=true` + `startSimulation()`（server.js 的 `startRealCollection()` 失败分支），平台停在模拟模式，直到你再次手动切换或重启。所以"切了 real 但页面还是模拟数据"是**设计行为**，不是 bug。

## 3. 切换前准备清单（Checklist）

从模拟切真实前，逐项核对，缺一项都可能切过去后没数据：

### 3.1 硬件与网络（真实 PLC 必需）

- [ ] PLC 通电、以太网口已接线，上位机 `ping PLC_IP` 通
- [ ] AutoShop 中 MBS 从站服务已使能：端口 502、站号与 `.env` 的 `PLC_UNIT_ID` 一致（默认 1）
- [ ] 上位机/服务器防火墙放行 502 出方向（云服务器场景：502 只走 frp 隧道或内网，**绝不直接暴露公网**）
- [ ] 现场传感器已接线（温度/压力/湿度 4-20mA → GL10-4AD），量程换算常数与程序一致（见操作手册 2.2）

### 3.2 .env 配置核对（最关键）

当前 `realtime-platform-main/.env` 状态：`PLC_MODE=simulation`，寄存器段为 **30001-30022（标准型段）**。

切真实模式时要确认三件事：

1. **PLC_MODE 改为 `real`**；
2. **PLC_HOST / PLC_PORT 指向真机**（或模拟器）；
3. **寄存器段必须与 PLC 里实际下载的程序一致**，这是最容易错的一步：

| 寄存器 | 标准型 H5U（D≥32767）默认段 | **H5U Easy / AutoShop 段**（参考程序 `plc-program/H5U_main.st` 默认用这段） |
|---|---|---|
| 温度/压力/湿度 | 30001 / 30002 / 30003 | **2001 / 2002 / 2003** |
| 状态字/序号 | 30004 / 30005 | **2004 / 2005** |
| 子包段 | 30011 | **2011** |
| 写回（力/高度） | 30021 / 30022 | **2021 / 2022** |

> 参考程序 `H5U_main.st` 默认按 **D2001-2022** 编写（Easy 安全段，D30001 在 Easy 上不存在）。若现场 PLC 下载的就是这份程序，`.env` 必须同步改成 2001 段；若你用的是标准型 H5U 且程序已换成 D30001 段，才保留默认 30001 段。**读错位一位 = 数据全乱**（排查见 6.4）。

推荐的真实 PLC 最小配置（Easy 型）：

```ini
# .env（realtime-platform-main 根目录）
PLC_MODE=real
PLC_HOST=192.168.1.88        # 改成现场 PLC 实际 IP
PLC_PORT=502
PLC_UNIT_ID=1
PLC_INTERVAL=2000            # 真实 PLC 建议 1000-2000

# 寄存器段与 PLC 程序一致（Easy 型 D2001 段）
PLC_REG_TEMP=2001
PLC_REG_PRESS=2002
PLC_REG_HUMID=2003
PLC_REG_STATUS=2004
PLC_REG_SEQ=2005
PLC_REG_SUB_BASE=2011
PLC_REG_WRITE_FORCE=2021
PLC_REG_WRITE_HEIGHT=2022
```

### 3.3 数据库（可选，但真实模式建议配）

真实模式会尝试初始化 Prisma（MySQL）。两种情况：

- **不配 DATABASE_URL**：日志出现 `⚠️ Prisma 加载失败，将以无数据库模式运行`，平台照常工作，但告警历史、用户登录等功能不落库（重启丢失）。
- **要落库**：准备一个 MySQL（本机 Docker 一条命令即可），在 `.env` 加：
  ```ini
  DATABASE_URL=mysql://用户名:密码@127.0.0.1:3306/realtime_platform
  ```
  然后执行建表（项目**没有** migrations 目录，用 db push）：
  ```bash
  npx prisma db push
  ```

### 3.4 阈值与模型标定（真实设备前必读）

- 平台侧阈值在 `plc-packet.js` 的 `THRESHOLDS`（高温 80°C / 低温 -10°C / 高压 1000kPa / 低压 100kPa / 高湿 85%），与 PLC 程序内判阈**必须一致**，改任何一侧都要同步另一侧。
- 接触力模型 `F = p×A_eff − F_offset`（EN 50367）：`PANTO_A_EFF` / `PANTO_F_OFFSET` 需现场实测标定（操作手册 8.4）。⚠️ 若真实气囊 A_eff 远大于默认 0.001，工作压力可能低于 100kPa，会持续报"低压报警"——此时要把低压阈值一起调到工作压力以下，并把 `PANTO_F_TARGET` 避开阈值。
- 真实控制参数（`PANTO_TAU_FORCE/HEIGHT/DEADTIME_MS`）默认值与模拟器一致，真实对象应在稳定后做一次 Z-N 阶跃整定获取（操作手册 7.6 / 8.6）。

## 4. 详细切换步骤

> 命令默认在 `D:\realtime-platform\realtime-platform-main` 目录执行。Windows 下 PowerShell 的 `curl` 是 `Invoke-WebRequest` 别名，请用 `curl.exe` 或 `Invoke-RestMethod`（文中两种写法都给出）。

### 4.1 场景一：先切到模拟器闭环（推荐第一站，无需 PLC）

目的：用模拟器验证"real 模式"整条链路（采集→解析→告警→写回→整定）在你这台机器上是通的，再动真机。

**步骤 1：改 .env 为模拟器闭环配置**

```ini
PLC_MODE=real
PLC_HOST=127.0.0.1
PLC_PORT=1502
PLC_INTERVAL=1000        # 配合模拟器建议 1000
```

（寄存器段用默认 30001 段即可，模拟器按协议地址提供服务。）

**步骤 2：终端 1 启动模拟器**

```bash
npm run plc-sim
# 看到日志：汇川 H5U PLC 模拟器（Modbus TCP 从站）监听: 0.0.0.0:1502
# 每 1s 一条：[主包] seq=... 温度=25.0°C 压力=250.00kPa 湿度=45.0% 状态=0x40
```

**步骤 3：终端 2 启动平台**

```bash
npm start        # = node server.js，前后端一体，访问 http://localhost:3000
```

**步骤 4：验证（详见第 5 章）**。成功后，进入 4.2 只需改 `PLC_HOST/PORT` 两个值。

### 4.2 场景二：本地开发永久切真实 PLC

**步骤 1：停掉平台**（Ctrl+C）。

**步骤 2：改 .env**（按 3.2 的核对表）：
- `PLC_MODE=simulation` → `PLC_MODE=real`
- `PLC_HOST` / `PLC_PORT` / `PLC_UNIT_ID` 指向现场 PLC
- `PLC_REG_*` 与 PLC 程序段一致
- （可选）加 `DATABASE_URL` 并 `npx prisma db push`

**步骤 3：先只读核对，不要急着开自动**。启动平台后按第 5 章验证数据；再用 ModbusPoll 直接读寄存器核对数值与状态字 bit6=0x40、序号每秒递增（操作手册 8.2）。确认平台读数与 ModbusPoll 一致，才进入下一步。

**步骤 4：小步开自动**。先在页面/API 只开力环自动，观察比例阀动作平稳、测量收敛，再开姿态环；有振荡先调小增益（操作手册 8.5 / 9.8）。

**步骤 5：Z-N 整定（可选但推荐）**。在稳态下先后对力环、姿态环各做一次（操作手册 7.6）。**生产运行中不要整定**。

**步骤 6：异常联调**。人为触发一路异常（断传感器线、堵比例阀），确认平台告警与现场一致（操作手册 8.7）。

### 4.3 场景三：运行中临时切换（不重启）

适合：快速验证、现场演示、排查"真实模式能否连上"。

**方式一：前端按钮** —— 打开受电弓监测页（MonitorCar），点"模拟/真实"切换按钮。成功提示"已切换到 真实 模式"；若 PLC 连不上，会提示并停留在模拟模式（页面显示"模拟数据"）。

**方式二：API（curl）**

```powershell
# 查当前模式
curl.exe http://localhost:3000/api/plc/mode
# 期望 {"mode":"simulation"}

# 切到真实模式（连不上会自动回退模拟）
curl.exe -X POST http://localhost:3000/api/plc/mode -H "Content-Type: application/json" -d "{\"mode\":\"real\"}"

# 切回模拟模式
curl.exe -X POST http://localhost:3000/api/plc/mode -H "Content-Type: application/json" -d "{\"mode\":\"simulation\"}"
```

观察平台终端日志：
- 成功：`✅ 切换到真实PLC模式`
- 失败：`❌ 汇川 PLC 连接失败 (...) → ⚠️ 真实PLC连接失败，自动切换到模拟模式`

> ⚠️ 记住 2.1 的三个事实：临时切换重启失效；改 .env 不重启则 API 仍连旧地址；启动时是模拟则切 real 也不落库。

### 4.4 场景四：Docker / 云服务器切换

**Docker Compose（云服务器，参考《云服务器部署方案.md》）**：

编辑 `/opt/realtime-platform/docker-compose.yml` 中 `app` 服务的环境变量：

```yaml
    environment:
      PLC_MODE: real                  # simulation → real
      PLC_HOST: 127.0.0.1             # frp 穿透后指向隧道端口
      PLC_PORT: 6050
      DATABASE_URL: mysql://rtp:密码@mysql:3306/realtime_platform
```

改完重建并重启容器：

```bash
cd /opt/realtime-platform
docker compose up -d --build app
# 或仅环境变量变化：docker compose up -d app
docker compose logs -f --tail=50 app   # 看是否 "✅ 切换到真实PLC模式"
```

**Railway（演示环境）**：在 Railway 控制台 Variables 里把 `PLC_MODE` 改成 `real` 并加 `PLC_HOST/PORT` 环境变量，Deploy 后生效。⚠️ Railway 海外节点连不了现场 PLC（UDP 受限、无法自建 frp 服务端），**实际只适合保持 simulation**；生产建议迁云服务器（部署方案 8.2）。

**云上接真实设备的网络前提**（部署方案第三章）：现场网关跑 frpc，把 PLC 502 映射到云服务器 6050、摄像头 554 映射到 7551，云端 `.env` 用 `PLC_HOST=127.0.0.1 PLC_PORT=6050`。**502/554 绝不直接暴露公网**。

### 4.5 场景五：切回模拟模式（回滚）

- **永久回滚**：`.env` 改回 `PLC_MODE=simulation`，重启平台。模拟器可停可留（留着也无害）。
- **临时回滚**：`POST /api/plc/mode {"mode":"simulation"}` 或前端按钮，立即生效。
- 切换后如页面残留 PLC 产生的告警，可调 `DELETE /api/simulation/clear` 清掉内存中的 `PLC_SENSOR` 告警记录（不影响数据库）。

## 6. 常见问题排查（切换场景专属）

| # | 现象 | 原因 | 处理 |
|---|---|---|---|
| 6.1 | 切了 real，页面还是"模拟数据" | PLC 连不上，平台自动回退模拟（**不会自动重试**） | 看平台日志的失败原因；ping 通、MBS 使能、端口对后，**再切一次或重启** |
| 6.2 | 重启后回到模拟模式 | `.env` 还是 `simulation`，或改的是 Docker/Railway 环境变量但没重建容器 | 确认 `.env`（或 compose 环境变量）已改并重建容器 |
| 6.3 | 改了 `.env` 地址，API 切换仍连旧地址 | 运行时切换不重读 .env（2.1 事实 1） | 改完 `.env` 必须重启 server |
| 6.4 | 数据全 0 / 读数错位 | 寄存器段与 PLC 程序不一致（30001 vs 2001），或 Modbus 工具加了 40001 偏移 | 用 ModbusPoll 直接核对；把 `PLC_REG_*` 全部 ±1 或整段切换到程序实际段 |
| 6.5 | 数值差 10 倍 | PLC 程序与平台缩放不一致（×10 vs ×100） | 统一为 ×10（压力用 ×10，见操作手册 4.1 溢出说明） |
| 6.6 | 切 real 后告警不落库 | 启动时是模拟模式，prisma 未初始化（2.1 事实 2）；或没配 DATABASE_URL | `PLC_MODE=real` + 配 `DATABASE_URL` + `npx prisma db push` + 重启 |
| 6.7 | Prisma 连接报错 | DATABASE_URL 的 host 写错（Docker 里要写服务名 `mysql` 而不是 localhost） | 按部署方案坑 1 核对连接串 |
| 6.8 | 页面显示"旧固件回退" | PLC 状态字 bit6=0 且序号=0（旧固件或重启后序号未恢复） | 属正常回退路径；确认 PLC 程序置位 0x40 或等序号递增 |
| 6.9 | 闭环中偶发"低压报警" | 目标压力压在低压阈值 100kPa 上（标定问题） | 调整 `THRESHOLDS.pressLow` 与 PLC 判阈，或调整目标值（3.4） |
| 6.10 | 模拟器跑着但平台连不上 | 模拟器端口被占用 / 平台 PLC_PORT 没指向 1502 | `netstat -ano | findstr 1502` 查占用；核对 `.env` 的 `PLC_PORT` |

## 7. 相关 API 速查

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/plc/mode` | 查当前模式（simulation / real） |
| POST | `/api/plc/mode` | 切换模式 `{"mode":"real"}` 或 `{"mode":"simulation"}` |
| GET | `/api/simulation/pause` | 查模拟数据是否暂停 |
| POST | `/api/simulation/pause` | 暂停/恢复模拟数据 `{"paused":true}` |
| DELETE | `/api/simulation/clear` | 清内存中 PLC_SENSOR 模拟告警 |
| GET | `/api/plc/packet` | 最近一次主/子包原始报文（排错用） |
| GET | `/api/control/status` | 双环 PID 状态（目标/测量/输出/增益/整定） |
| POST | `/api/control/auto` | 自动调节开关 `{"loop":"force","enabled":true}` |
| POST | `/api/control/tune` | 启动 Z-N 整定 `{"loop":"force"}`（从稳态开始） |
| POST | `/api/control/tune/cancel` | 取消整定 |

## 8. 一页速记

```
纯模拟(simulation) ──改 .env PLC_MODE=real + PLC_HOST/PORT + 重启──► 模拟器闭环(127.0.0.1:1502)
模拟器闭环 ──只改 PLC_HOST/PORT 指向真机 + 重启──► 真实 PLC(192.168.1.88:502)
任意时刻：POST /api/plc/mode 或页面按钮 = 临时切换（重启失效）
切 real 连不上 → 自动回退模拟，且不自动重试 → 修好后再切一次
启动时是 simulation → 切 real 也不落库 → 要落库必须 real 启动 + DATABASE_URL
```
