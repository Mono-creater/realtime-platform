## 1 平台概述

### 1.1 平台做什么

本平台面向城市轨道交通受电弓碳滑板的**在线监测、故障告警与接触状态主动调控**，核心能力包括：

| 能力 | 说明 |
|---|---|
| 数据采集 | 温度、压力、湿度三路 4～20 mA 传感器经 PLC 采集；可选接入现场相机图像/视频 |
| 实时监测 | 实时曲线、仪表盘、线路/单车/全局多级视图，Socket.IO 推送 |
| 异常告警 | 越限告警 + **变化率预警**、分级（warning / major / critical）、确认与解除留痕 |
| 主动控制 | 双环 PID（接触力环 + 姿态环）自动调节，支持参数下发与 Z-N 阶跃整定 |
| 健康与检修 | 健康指数与四档检修建议、告警自动生成工单、工单流转与审计 |
| 数据资产 | 历史查询、超限快照、照片上传、PDF 报告导出 |
| 链路可信 | 丢包率统计、数据质量码、写入—回读校验、断线重连退避 |

### 1.2 系统组成与数据流

```
传感器(3×4-20mA) → GL10-4AD → 汇川 H5U PLC ── Modbus TCP(FC03 读) ──→ 平台服务端 server.js
                                        ↑                                   │
                                        └── FC16 写(30021/30022) ────────────┘
                                                                             │
                                          Prisma/MySQL（告警、快照、用户）←──┤
                                                   uploads/（照片）    ←──────┤
                                                                             ↓
                                                     Socket.IO 实时推送 → 浏览器（Vue3 大屏）
可选：PLC模拟器（无硬件联调）／现场摄像头(RTSP) → 流媒体 → 浏览器
```

- **采集侧**：PLC 每 100 ms 采样，10 点滑窗均值（约 1 s 出一个均值），阈值判定、主包/异常子包组包。
- **平台侧**：解析报文 → 异常判定与告警入库 → 双环 PID 控制运算 → 控制量回写 PLC → 实时推送前端。
- **控制白名单**：平台只写两个寄存器——`30021`（气囊压力设定 ×10 kPa）与 `30022`（弓头高度设定 mm）。

### 1.3 三种运行模式

| 模式 | `PLC_MODE` | 数据来源 | 控制回路 | 用途 |
|---|---|---|---|---|
| 真实 PLC | `real` + 实体 PLC IP | 现场 H5U 主包/子包 | 真实闭环（FC16 写回） | 现场运行 |
| 模拟器闭环 | `real` + `PLC_HOST=127.0.0.1:1502` | 本机 `plc-simulator.js` | 真实 Modbus 闭环 | 无硬件联调（推荐） |
| 纯模拟 | `simulation` | 平台自生成数据 | 平台内部对象模型 | 界面/告警演示 |

### 2.1 软硬件要求

### 2.2 安装依赖

```bash
cd D:\realtime-platform\realtime-platform-main
npm install            # 安装依赖（含 express、socket.io、prisma、modbus-serial、echarts 等）
```

### 2.3 数据库初始化

> 本机（开发机）**已完成**本节全部步骤并在 2026-09-18 实测通过落库，配置见 §3.6。换新机器时按下面 5 步重做一遍。

1. 创建数据库与专用账号（不要用 root 跑平台）：
   ```sql
   CREATE DATABASE realtime_platform CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
   CREATE USER 'rtp'@'localhost' IDENTIFIED BY '你的强口令';
   CREATE USER 'rtp'@'127.0.0.1' IDENTIFIED BY '你的强口令';
   GRANT ALL PRIVILEGES ON realtime_platform.* TO 'rtp'@'localhost';
   GRANT ALL PRIVILEGES ON realtime_platform.* TO 'rtp'@'127.0.0.1';
   FLUSH PRIVILEGES;
   ```
2. 在 `.env` 中配置连接串（Prisma 约定的变量名）：
   ```
   DATABASE_URL="mysql://rtp:你的强口令@127.0.0.1:3306/realtime_platform"
   ```
3. **安装 Prisma CLI**（关键：工程原本只装了 `@prisma/client`，**没有 CLI、也从未生成过客户端**，只配连接串仍然连不上库）：
   ```bash
   npm install --save-dev prisma@5.22.0
   ```
4. 生成客户端并建表：
   ```bash
   npx prisma generate --schema prisma/schema.prisma
   npx prisma db push  --schema prisma/schema.prisma    # 本工程没有 migrations 目录，用 db push
   # 期望输出：Your database is now in sync with your Prisma schema.
   # 快速查看数据：npx prisma studio
   ```
   > `prisma generate` 会自行下载查询引擎，生成后可见 `node_modules/.prisma/client/query_engine-windows.dll.node`（约 19 MB）。
   > 新版 npm 默认不执行依赖的安装脚本（提示 `packages have install scripts not yet covered by allowScripts`），**不影响使用**，但换机器部署时务必手动执行一次 `prisma generate`。
5. **重启平台**：数据库只在启动瞬间按 `PLC_MODE` 加载，运行中切换模式不会加载数据库。
   - 成功：`✅ Prisma Client 已初始化` → `✅ 当前加载 N 条记录`
   - 失败：`⚠️ Prisma 加载失败，将以无数据库模式运行`（告警只存内存，重启即丢）

6. 数据表：`warning_history`（告警历史）、`over_limit_snapshot`（超限快照）、`users`（用户与角色）。
   > 注：工程内另有一份历史 schema（`realtime-platform/prisma/schema.prisma`，PostgreSQL，含摄像头检测扩展字段）。
   > **以根目录 `prisma/schema.prisma` 为准**；若要启用摄像头扩展字段，请把扩展字段合并到根 schema 后重新建表。

### 2.4 构建与启动

| 场景 | 命令 | 说明 |
|---|---|---|
| 前端开发（热更新） | `npm run dev` | Vite 开发服务器，接口走同源代理 |
| 生产构建 | `npm run build` | 产物输出到 `dist/`，由 Express 直接托管 |
| 生产启动 | `npm start` | `node server.js`，默认监听 `PORT=3000`（一个服务全包） |
| 代码检查 | `npm run lint` | oxlint + eslint |

访问：`http://<服务器IP>:3000`

### 2.5 容器化部署（可选）

工程自带 `Dockerfile`（node:22-alpine）、`railway.json`、`nixpacks.toml`：

```bash
docker build -t realtime-platform .
docker run -d --name rtp -p 3000:3000 --env-file .env \
  -v /data/uploads:/app/uploads realtime-platform
```

- `uploads/` 必须挂载持久化卷，否则容器重建会丢照片。
- 云服务器选型、带宽与视频回传（ZLMediaKit / GB28181）、frp 隧道打通现场 PLC 与摄像头的完整方案见《云服务器部署方案.md》。

### 2.6 与现场设备的网络连通

现场 PLC（`502`）与摄像头（`554`）位于局域网，云端平台无法直连，推荐做法：

```
云服务器(公网) ←─frp/WireGuard 隧道─→ 现场网关(工控机/N1盒子) ─→ H5U PLC(502) / 相机(554)
```

云端 `.env` 指向隧道本机端口（如 `PLC_HOST=127.0.0.1`、`PLC_PORT=6050`），**平台代码无需修改**。
⚠️ Modbus 与 RTSP 均无鉴权加密，**严禁把 502/554 直接映射到公网**。

## 3 环境变量配置

复制模板并修改：`copy .env.example .env`

### 3.1 运行模式与 PLC 连接

| 变量 | 默认 | 说明 |
|---|---|---|
| `PLC_MODE` | `real` | `real`=读 PLC/模拟器；`simulation`=平台自生成数据 |
| `PLC_HOST` | `192.168.1.88` | PLC 或模拟器地址（模拟器本机填 `127.0.0.1`） |
| `PLC_PORT` | `502` | Modbus TCP 端口（模拟器默认 `1502`） |
| `PLC_UNIT_ID` | `1` | 从站号，须与 PLC/模拟器一致 |
| `PLC_INTERVAL` | `2000` | 平台采集周期 ms（真实 PLC 建议 1000～2000；配模拟器可设 1000） |
| `PLC_WINDOW` | `10` | 旧固件回退路径的缓冲条数（扩展协议下不生效） |

### 3.2 寄存器地址（协议原地址，不做 40001 偏移）

| 变量 | 默认 | 说明 |
|---|---|---|
| `PLC_REG_TEMP` / `PRESS` / `HUMID` | `30001/30002/30003` | 温度/压力/湿度 10 次均值（×10；温度有符号） |
| `PLC_REG_STATUS` | `30004` | 状态字：bit0～2 异常、bit6 扩展协议、bit7 子包有效 |
| `PLC_REG_SEQ` | `30005` | 主包序号（65535 回绕，0 表示旧固件） |
| `PLC_REG_SUB_BASE` | `30011` | 异常子包起始（序号、位图、异常值） |
| `PLC_REG_WRITE_FORCE` | `30021` | **写**：接触力环输出＝气囊压力设定（×10 kPa，FC16） |
| `PLC_REG_WRITE_HEIGHT` | `30022` | **写**：姿态环输出＝弓头高度设定（mm，FC16） |

> ⚠️ **H5U Easy 型** D 区仅 `D0～D8191`，**不存在 D30001**：需将 `plc-program/H5U_main.st` 改用 `D2001～D2022` 段，并同步修改上表变量（如 `PLC_REG_TEMP=2001`）。

### 3.3 接触力模型与运动学

| 变量 | 默认 | 说明 |
|---|---|---|
| `PANTO_A_EFF` | `0.001` | 气囊有效面积 m²（**需现场标定**） |
| `PANTO_F_OFFSET` | `0` | 弹簧/重力补偿偏置 N（**需现场标定**） |
| `PANTO_F_TARGET` | `100` | 接触力目标 N（EN 50367 静态接触力 70～120 N） |
| `PANTO_L1` / `PANTO_L2` | `1200` / `1300` | 下臂/上臂杆长 mm |
| `PANTO_THETA_RATIO` | `0.8` | 两连杆角度比例 θ2＝r·θ1 |
| `PANTO_H_TARGET` | `2400` | 弓头高度目标 mm |

接触力关系：`F = p_air × PANTO_A_EFF − PANTO_F_OFFSET`（N）

### 3.4 控制与整定

| 变量 | 默认 | 说明 |
|---|---|---|
| `CONTROL_INTERVAL` | `500` | 控制周期 ms |
| `PANTO_TAU_FORCE` / `PANTO_TAU_HEIGHT` | `2.0` / `0.5` | 通道一阶时间常数 s（真实值由辨识确定） |
| `PANTO_DEADTIME_MS` | `600` | 比例阀+管路纯滞后 ms（Z-N 拟合要求 L>0） |

| `ZN_DEBUG` | `0` | 置 1 打印拟合中间量（排错用） |

## 4 三种运行模式与首次配置

### 4.1 纯模拟模式（无任何硬件，最快演示）

1. `.env` 设 `PLC_MODE=simulation`；
2. `npm start`（或 `npm run dev`）；
3. 浏览器打开 `http://127.0.0.1:3000`，页面即出现自生成数据与告警。
> 用途：评审演示、前端联调。注意此模式**不产生 Modbus 报文**，不能验证通信链路与控制回写。

### 4.2 模拟器闭环模式（推荐联调方式）

模拟器在 **Modbus 协议层**忠实模拟 H5U：同样的寄存器、状态字、序号回绕、异常子包语义与写回寄存器，并带一阶滞后执行机构模型，平台无法区分它与真机。

**启动顺序（两个终端）**：

```bash
# 终端 1：启动 PLC 模拟器（默认 0.0.0.0:1502）
npm run plc-sim                     # 正常工况
npm run plc-sim:anomaly             # 注入高温异常（temperature:high）
npm run plc-sim:closedloop          # 带 --debug，打印原始寄存器（观察控制回写）

# 终端 2：平台指向模拟器
# .env: PLC_MODE=real  PLC_HOST=127.0.0.1  PLC_PORT=1502  PLC_UNIT_ID=1
npm start
```

**验证清单**：

| 检查项 | 方法 | 期望 |
|---|---|---|
| 通信正常 | 页面实时数据持续刷新；`GET /api/plc/packet` | 温度≈25 ℃、压力≈250 kPa、湿度≈45 %RH |
| 状态字解析 | `GET /api/plc/packet` | 正常时无异常位；注入异常后对应位置 1 |
| 告警链路 | 用 `npm run plc-sim:anomaly` 重启模拟器 | 页面出现分级告警并入库 |
| 控制回写 | 开启自动调节后看模拟器 `--debug` 输出 | 平台写入 30021/30022 的值随之变化 |
| 数据落库 | `npx prisma studio` 查看 `warning_history` | 告警记录与时间、等级字段正确 |

模拟器常用参数（命令行优先于 `.env`）：

```bash
node plc-simulator.js --port 1502 --unit 1 --interval 100 \
     --base-temp 25 --base-press 250 --base-humid 45 \
     --anomaly temperature:high,pressure:low --debug
```

### 4.3 真实 PLC 模式

**第一步：硬件接线**

| 传感器 | 量程 | 4 mA | 20 mA | 接入 GL10-4AD |
|---|---|---|---|---|
| 温度变送器 | −10～80 ℃ | −10 ℃ | 80 ℃ | CH0 |
| 压力变送器 | 0～1000 kPa | 0 kPa | 1000 kPa | CH1 |
| 湿度变送器 | 0～100 %RH | 0 % | 100 % | CH2 |

要点：模块 24 V DC 供电；屏蔽线单端接地（PLC 柜侧）；下载程序前用万用表确认 4 mA 基流。

**第二步：AutoShop 配置**

1. 设置 PLC IP（如 `192.168.1.88`，与上位机同网段），上位机 ping 通；
2. 启用 **MBS 从站**（Modbus TCP），端口 `502`，站号与 `.env` 的 `PLC_UNIT_ID` 一致；
3. 确认 4x 保持寄存器 ↔ D 软元件映射（H5U 为 `4xN ↔ DN` 直接对应）；
4. **地址为协议原值**，不要加 40001 偏移。

**第三步：下载程序**

1. 将 `plc-program/H5U_main.st` 导入 ST 程序，替换 5 处占位软元件（三路 AD 通道、比例阀输出、升弓机构输出）；
2. 确认 100 ms 脉冲继电器（程序用 `SM4010`）与所用软元件一致；
3. 编译 → 下载 → **重新上电**；
4. 用 ModbusPoll 读 `4x2001～2005`（Easy 段）或 `30001～30005`（标准段）核对数值与状态字。

**第四步：平台侧**

```
PLC_MODE=real
PLC_HOST=192.168.1.88
PLC_PORT=502
PLC_UNIT_ID=1
PLC_INTERVAL=1000          # 建议 1000～2000 ms
PLC_REG_* = 实际使用的 D 区段地址
```

**第五步：联调顺序**：接线检查 → 量程换算核对 → 寄存器核对 → 告警验证 → 控制回写验证 → 页面刷新确认。

### 4.4 运行模式切换

- 页面切换：设置入口选择“真实 PLC / 模拟 / 暂停”；
- 接口切换：`GET /api/plc/mode` 查询、`POST /api/plc/mode` 切换；`GET|POST /api/simulation/pause` 暂停/恢复模拟数据；
- **切换后自检**：① 数据是否恢复刷新；② 质量码是否 GOOD；③ 控制环是否需要重新投入自动（建议先手动、再自动投入，避免输出跳变）。

## 6 控制功能操作

> 控制前提：`PLC_MODE=real`（真实 PLC 或模拟器闭环）；纯模拟模式下控制在平台内部模型上运行，仅用于演示。

### 6.1 自动调节启停

- 入口：单车监测页“自动调节”开关（接口 `POST /api/control/auto`）。
- **无扰切换**：投入自动时，控制器以当前输出预载积分，避免输出跳变；大偏差工况下允许方向正确的输出阶跃。
- 状态查询：`GET /api/control/status` → 返回两个环的目标、测量、误差、输出、Kp/Ki/Kd、饱和标志、限幅区间。

### 6.2 手动下发参数

`POST /api/control/params`，可下发 `kp`、`ki`、`kd`、`target`：

- 参数必须为非负数字，否则接口报错；
- `target` 必须落在可实现范围内（接触力环按 `p·A_eff` 折算，姿态环按 1000～2600 mm），越界报错；
- 正在整定的回路**不允许**改参，需先取消整定。

### 6.3 Z-N 阶跃整定

**操作步骤**：

1. 确认该回路处于可整定状态（另一回路未在整定中）；
2. `POST /api/control/tune` 启动（可带回路名），平台立即施加 **10% 量程阶跃**（默认 95 kPa）；
3. 观察 `GET /api/control/status` 中 `tune.state`：`sampling → fitting → done/failed`；
4. `done` 后自动写入新参数并恢复整定前的自动状态；`failed` 时读取 `tune.error`；
5. 取消：`POST /api/control/tune/cancel`。

**判读要点**：

| 现象 | 原因 | 处理 |
|---|---|---|
| `采样点不足，无法拟合` | 阶跃期间数据中断 | 检查通信与采集周期 |
| `响应无变化 / 未偏离基线` | 执行机构未动作、阶跃幅值过小 | 检查比例阀/气路，增大 `ZN_STEP_PCT` |
| `纯滞后占比过大（T ≤ L），Z-N 不适用` | 通道时间常数小于纯滞后（如姿态环） | **改用 IMC 整定**（见 6.4），姿态环保留保守参数 |
| 整定后超调大、长时间不进误差带 | Z-N 在 L/T 偏大时过于激进 | 使用 v2 安全整定与斜坡预设（见 6.4） |

### 6.4 v2 安全整定与推荐预设（本次优化新增）

```js
const { createControlEngineV2, tuneSafe, PRESETS } = require('./control-engine-v2');

// 1) 安全整定：T>L 时按纯滞后占比折减 Z-N 增益；T≤L 时自动切换 IMC-PI
const g = tuneSafe(K, T, L);        // { ok, method, kp, ki, kd, reason }

// 2) 推荐预设（含不完全微分、积分分离、设定值斜坡）
PRESETS.contactForce   // { derivFilterN: 8, integralSeparation: 0.35, rampRate: 3 }   N/s
PRESETS.posture        // { derivFilterN: 8, integralSeparation: 0.35, rampRate: 100 } mm/s

// 3) 速度自适应目标接触力（按标准公式，随车速自动调整）
const eng = createControlEngineV2({ system: 'AC' });
eng.setSpeed(80);                   // Fm = 0.00097·80² + 70 ≈ 76.2 N
```

**实测效果（`node tests/run-tests.js`）**：

| 场景 | 改造前 | 改造后 |
|---|---|---|
| 接触力环（K=0.9923、T=1.7046 s、L=1.0078 s） | 直接套 Z-N：超调 **83.9%**；出厂保守参数：15.7% | 安全预设：超调 **3.68%**、15.5 s 进入 ±2% 带、稳态偏差 0 |
| 姿态环（T=0.5 s ≤ L=0.6 s） | Z-N **不可用** | 自动 IMC：超调 **3.66%**、8.5 s 稳定 |

### 6.5 控制效果验收判据

| 指标 | 建议判据 |
|---|---|
| 超调量 | ≤5% |
| 调节时间（进入 ±2% 带） | 接触力环 ≤20 s；姿态环 ≤30 s |
| 稳态偏差 | 接触力 ≤0.5 N；姿态 ≤2 mm |
| 接触力合规 | `GET /api/v2/standards/check?v=..&mean=..&std=..` 返回 `ok=true` |

## 7 告警、健康评估与工单

### 7.1 分级阈值（默认值，需按线路标定）

| 参数 | warning | major | critical | 变化率预警（/min） |
|---|---|---|---|---|
| 温度 | >80 ℃、<−10 ℃ | >90 ℃、<−20 ℃ | >100 ℃ | ≥2（major ≥5） |
| 压力 | >1000 kPa、<100 kPa | >1100 kPa、<80 kPa | >1200 kPa | ≥80（major ≥200） |
| 湿度 | >85 %RH | >92 %RH | >97 %RH | ≥5（major ≥12） |

> 阈值取自现场既有配置；分级与变化率阈值为可标定默认值，投运前按运营单位检修规程标定。

### 7.2 变化率预警（缓变早发现）

对缓慢漂移（如 3 ℃/min 温升），阈值判据要等越限才报警；变化率判据可在越限前给出预警。
实测：3 ℃/min 缓升场景下，发现时延由 **401 s 缩短到 2 s**。

### 7.3 健康指数与检修建议

`GET /api/v2/health?forceMean=..&forceTarget=..&forceStd=..&tempMax=..&alarmCount24h=..`

| 分值 | 等级 | 建议 |
|---|---|---|
| ≥85 | 正常 | 按周期巡检，保持常规监测 |
| 70～84 | 关注 | 加密监测频次，纳入下次天窗复检 |
| 55～69 | 计划检修 | 安排计划检修，检查气路与接触压力 |
| <55 | 立即检修 | 触发紧急工单，停运检查碳滑板与受电弓 |

> 健康指数为**代理指标**（接触力偏差、波动、温度越限、告警频次四项加权），接入滑板厚度/磨耗量后应替换为 RUL 模型输出。

### 7.4 工单闭环

- 自动生成：`major` / `critical` 告警可自动建单（`autoCreateOrder`）；
- 状态机：新建 → 指派 → 处理中 → 完成 → 复核 → 关闭（可取消）；
- 流转接口：`POST /api/v2/orders/:id/assign|start|complete|verify|cancel`；
- 审计：每次流转记录操作人、时间、备注；MTTR 由 `GET /api/v2/kpi` 给出。

## 9 故障排查

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 页面无数据 | `PLC_MODE` 配错；PLC 不可达；端口/站号不符 | 先 `ping` PLC，再用 ModbusPoll 读寄存器；核对 `.env` |
| 数据一直不刷新 | 采集周期过长；轮询相位；模拟器未启动 | 调小 `PLC_INTERVAL`；确认模拟器进程存活 |
| 告警不产生 | 阈值过高；确认点数未满足；抑制窗口内 | 核对阈值；检查 `confirmN`；等待抑制窗口结束 |
| 告警抖动频繁 | 无滤波、阈值贴近稳态值 | 启用中值滤波＋连续确认（v2 默认已启用）；适当调整阈值 |
| 控制输出无动作 | 未投入自动；写寄存器地址错；比例阀未接线；写失败 | 看 `/api/control/status` 的 `auto`；核对 30021/30022；检查写回读校验日志 |
| 整定失败“T ≤ L” | 该通道纯滞后占比过大（姿态环） | 使用 IMC 整定（v2 `tuneSafe` 已自动切换） |
| 整定后振荡 | Z-N 参数激进 | 使用 v2 安全预设（折减增益＋斜坡） |
| 数据偶发跳变 | 电磁干扰、接线松动 | 检查屏蔽与接地；启用滤波；检查端子 |
| 通讯时断时续 | 网络抖动、隧道不稳 | 看 `/api/v2/link` 丢包率与质量码；检查 frp/VPN；确认退避重连生效 |
| 写操作无效果 | 回读不一致（写丢） | 查看 `link-monitor` 写回读记录；检查 PLC 写权限与寄存器映射 |
| 中文乱码 | 控制台编码 | 使用 UTF-8 终端；文件保存为 UTF-8 |
| 数据库连不上 | `DATABASE_URL` 错误 / MySQL 未启动 / 账号无权限 | 核对连接串；`Test-NetConnection 127.0.0.1 3306`；用 `mysql -h 127.0.0.1 -u rtp -p` 直连验证 |
| 启动报 `PrismaClient did not initialize yet` | 只装了 `@prisma/client`，从未执行 `prisma generate`（空壳客户端） | `npm install --save-dev prisma@5.22.0` 后 `npx prisma generate`（§2.3 第 3～4 步） |
| 日志出现「跳过数据库加载（模拟模式）」 | 该提示含义是"无数据库、告警存内存"，与 PLC 模式无关 | 按 §3.6 补 `DATABASE_URL` 并**重启**；以 `✅ Prisma Client 已初始化` 为准 |
| 写接口返回 401 | 已启用 `API_TOKEN` 但请求没带令牌 | 加请求头 `X-API-Token: <令牌>` 或 `Authorization: Bearer <令牌>`；前端场景由反向代理注入（§3.7） |
| 写接口返回 429 | 触发按 IP 写请求限流 | 降低操作频率，或按需调大 `RATE_LIMIT_PER_MIN`；响应头 `Retry-After` 给出等待秒数 |
| 上传返回 400「不支持的文件类型」 | 扩展名不在 `UPLOAD_ALLOWED_EXT` 白名单内 | 换用受支持格式，或按需扩充白名单（§3.7） |
| 上传返回 413 | 文件超过 `UPLOAD_MAX_MB` | 压缩后重传，或调大上限 |
| `/api/v2/*` 返回 404 | 平台版本过旧（未挂载 v2 路由） | 更新到含 `security.js` / `upgrade-routes.js` 挂载的版本；启动日志应出现「🔌 v2 升级接口已挂载」 |

日志与自检入口：`GET /api/test`、`GET /api/plc/packet`、`GET /api/v2/kpi`、`ZN_DEBUG=1` 打印整定过程。

### 9.1 模拟器启动失败排查（本次已加固）

## 10 安全与合规

> 本章第 1、5、6 条已由 `security.js` **落地实现**（v1.2 加固），不再是"建议项"；第 4 条属现场网络边界，须由部署方保证。

1. **写操作白名单**：平台仅允许写 `30021`、`30022` 两个寄存器；不得开放任意寄存器写入。
2. **写回读校验**：每次写入后回读比对，偏差超限即判失败并记录（`link-monitor` 的 `writeLog`）。
3. **最小权限与账号**：`users` 表含 `role` 字段（默认 `viewer`）；生产环境应启用登录鉴权，并对控制类接口做角色校验。
4. **网络边界**：Modbus(502)/RTSP(554) **不得暴露公网**，必须走隧道/VPN，隧道口仅对平台服务器 IP 开放。
5. **写接口保护（已实现）**：`security.js` 对全部写操作（POST/PUT/PATCH/DELETE）提供——
   - **令牌校验**：`.env` 设 `API_TOKEN` 即启用，请求需带 `X-API-Token` 或 `Authorization: Bearer`，否则 `401`；未设置时保持原放行行为（不破坏现网）。
   - **频率限制**：按来源 IP 令牌桶，默认 120 次/分，超配额返回 `429` 并带 `Retry-After`。
   - **操作审计**：环形缓冲记录写操作的时间、IP、方法、路径、状态码与耗时，`GET /api/v2/audit` 查询，`GET /api/v2/security` 查看当前策略。
6. **上传与数据合规（已实现）**：`/api/upload` 按扩展名白名单放行（默认 `jpg,jpeg,png,webp,gif,bmp,mp4,webm,mov,pdf`），**阻断 `.html/.js/.svg` 等可执行载荷**；超限返回 `413`。现场照片与告警记录按单位要求保留期限存储，对外提供数据时脱敏。
7. **控制参数约束**：PID 增益超过 `PID_GAIN_LIMIT`（默认 100）直接拒绝，目标值必须落在该回路可实现测量范围内，防止误设导致执行机构剧烈振荡。

### C. 标准与公式

| 项目 | 公式/限值 |
|---|---|
| 目标平均接触力（交流） | `Fm(v) = 0.000 97·v² + 70`（N，v 为 km/h） |
| 目标平均接触力（直流） | `Fm(v) = 0.001 55·v² + 70` |
| 动态接触力判据 | `σ ≤ 0.3·Fm`，`Fmax ≤ Fm + 3σ`，`Fmin ≥ Fm − 3σ` |
| 接触力—气压关系 | `F = p_air × A_eff − F_offset` |
| 弓头高度（两连杆） | `H = L1·sinθ1 + L2·sin(r·θ1)`，二分法反解 θ1∈[0°, 88°] |
| PID（位置式并联、微分先行） | `u = Kp·e + Ki∫e dt − Kd·dy/dt`（含条件积分抗饱和） |
| Z-N（开环阶跃） | `Kp = 1.2T/(K·L)`，`Ti = 2L`，`Td = 0.5L` |
| IMC-PI | `Kc = T/(K(λ+L))`，`Ti = T`，`Td = 0` |
| 安全折减 | 增益折减系数 `r = 1/(1+L/T)`（限幅 0.4～1） |

> 标准系数来源 EN 50367 / TB/T 3271 的公开形式；工程实施前须按项目采用的标准版本复核，可在 `standards.js` 中覆盖配置。
